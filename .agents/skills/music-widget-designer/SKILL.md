사용자가 원하는 구도·비율·질감과 필요한 기능을 우선한다. 미적 선택은 자율적으로 하고, 제목과 재생 버튼만 있는 디자인부터 복잡한 플레이어까지 필요한 기능만 선택한다. 배경·장식은 자유롭게 PNG로 제작하고, 곡 정보와 조작은 독립된 런타임 요소로 둔다. 기존 디자인을 고정 템플릿으로 강제하지 않는다.

먼저 [실행 규격](references/runtime.md)과 [지원 기능](references/capabilities.json)을 읽고 필요한 속성은 [스키마](references/schema.json)에서 확인한다. 새 제작은 version=2, 최소 APK 0.3.0을 기준으로 한다. 기존 v1 테마도 실행 가능하다. 알 수 없는 효과나 실행 코드를 manifest에 만들지 않는다.

## 폰트 선택
모든 디자인의 텍스트 폰트는 [눈누](https://noonnu.cc/index)에서 디자인에 가장 어울리는 것을 선택한다. 한국어뿐 아니라 영문 중심 테마에도 적용한다. 눈누는 탐색 창구이며 실제 TTF/OTF는 원 제작자의 배포처에서 받는다. 눈누 상세 페이지, 원 배포 URL, 원 라이선스를 읽어 임베딩·패키지 재배포를 확인하고 fonts에 기록하고 LICENSE.txt에 저작권 고지와 전문을 동봉한다. 단순히 '무료'라는 이유로 허용된다고 판단하지 않는다. WOFF/WOFF2 웹폰트 URL을 manifest에 넣지 않는다.

네트워크가 막힌 제작 환경에는 눈누에서 선택하고 원 배포처의 OFL을 동봉한 examples/orbit/assets/SUITE-Medium.ttf를 사용할 수 있다. 다른 스타일이 필요한데 폰트를 구할 수 없으면 이 제약을 짧게 알린다. 다른 폰트를 눈누에서 받았다고 꾸미지 않는다. 한글·영문·숫자 글리프를 검사하며 시스템 대체 폰트로 누락을 숨기지 않는다.

## 제작과 자동 수정
1. 사용자 레퍼런스로 비율과 레이어를 설계한다. 새 디렉터리와 고유 id를 사용한다. examples/orbit는 v2 문법 참고용이며 그대로 따를 디자인이 아니다.
2. 이미지 마스크·회전·원근·그룹·텍스트 정렬과 overflow를 조합한다. 움직임은 디자인이 요구할 때만 사용한다. 음파는 실제 캡처 기능이 없으므로 simulated 또는 static이라고 설명한다.
3. `python scripts/build.py THEME_DIR OUTPUT_DIR`를 실행한다. 한 번에 패키징·검증·폰트 점검·재생/일시정지/긴 한글/정보 누락 근사 이미지·contact-sheet·review.json을 만든다. 출력은 원본 폴더 밖에 둔다.
4. 생성 이미지를 직접 열고 레퍼런스 충실도, 글자 잘림, 대비, 버튼 위치와 터치 크기를 검사한다. errors는 고치고 warnings는 실제 디자인 맥락에서 해결하거나 전달한다. 최대 3회의 수정·재검증으로 수렴시키고, 남은 본질적 문제만 보고한다. 스크립트 성공을 시각적 검토 완료로 간주하지 않는다.
5. Android 실행 환경이 있으면 `--android-serial SERIAL --adb ADB_PATH`를 덧붙인다. [Android 검증](references/android-verification.md)의 실제 런타임/호스트 캡처를 열어 확인하고 수정한다. 기기가 없으면 근사 미리보기와 Android 미검증을 명확히 구분한다. 일반 ChatGPT/Claude 파일 실행 환경만으로 Android나 One UI 검증이 되었다고 주장하지 않는다.
6. 검증한 .mwidget, 미리보기, 짧은 기능·폰트·검증 범위 설명을 전달한다. 파일 실행이나 ZIP 접근을 못 하는 환경에서는 완성 파일을 만들었다고 말하지 않는다.

추가 권한이나 본질적 기능 변경을 제외한 디자인 선택을 사용자에게 반복해서 묻지 않는다. 임의 JavaScript, 외부 네트워크, 실행 파일은 패키지에 포함하지 않는다. 오픈소스 에셋은 배포 조건과 고지를 지키면 사용할 수 있다. 같은 id 재가져오기는 해당 테마를 쓰는 모든 위젯을 갱신하므로 독립 디자인에는 다른 id를 쓴다.
