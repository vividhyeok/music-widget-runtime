# v0.5.0 테마 삭제와 간결한 목록

테마 카드에는 이름, 실제 렌더러 미리보기와 ＋/⋮ 아이콘만 상시 표시한다. ＋는 홈 화면 추가, ⋮는 기존 위젯에 적용·테마 정보·삭제다. 반복되던 샘플 안내는 목록 상단 한 번만 표시한다. 정상 미리보기의 재시도 버튼과 상태 문구는 숨기고, 실패할 때만 복구 아이콘과 안내를 보여준다. 기존 위젯 설정은 한 줄 이름과 톱니 아이콘으로 표시하며 음악 연결 상태 자체를 눌러 설정을 연다. 아이콘은 48dp 터치 영역과 접근성 이름을 갖는다.

## 삭제 동작
- 삭제 확인 후 앱이 보관한 해당 테마의 모든 읽을 수 있는 이전 리비전과 현재 리비전을 정리한다. 휴대폰의 원본 .mwidget 파일은 삭제하지 않는다.
- 사용 중이면 대체 테마를 고른다. 대체 패키지를 검증하고, 연결된 위젯의 테마 선택과 삭제 대상의 등록 해제를 한 번의 SharedPreferences commit으로 저장한 뒤 파일을 정리한다. 플레이어 설정과 다른 테마는 유지한다.
- 삭제 작업은 위젯 렌더링과 같은 직렬 worker에서 실행해 진행 중인 위젯 이미지 생성과 파일 삭제가 겹치지 않게 한다. 가져오기와 삭제 저장소 작업도 동기화한다.
- 대체 테마가 없는 사용 중인 기본 테마는 삭제하지 않고 먼저 다른 테마를 가져오도록 안내한다. 다른 사용자 테마만 남아 있다면 기본 테마 복원을 대안으로 제공한다.
- 사용하지 않는 마지막 테마는 삭제할 수 있다. 기본 테마도 삭제 상태를 기억해 앱을 다시 열었을 때 자동으로 나타나지 않는다. 빈 목록과 새 위젯 설정에는 명시적인 기본 테마 복원 경로를 제공한다.
- 파일 일부를 정리하지 못하면 그 사실을 알린다. 삭제 취소 시 등록 정보나 위젯을 바꾸지 않는다.

검증: 기존 Android 회귀10개에 삭제 회귀3개를 추가했다. 다른 테마와 플레이어 보존, 잘못된 대체 테마에서 변경 없음, 이전 리비전 정리, 기본 테마 재등장 방지와 명시적 복원을 검사한다. 연결 기기에서는 ui-check가 실제 ⋮ 메뉴의 삭제 확인을 연 뒤 취소하고 설정 동일성을 검사한다. delete-check는 무작위 ID의 테스트용 테마를 두 번 가져온 뒤 그 테마만 삭제해 두 리비전 정리와 원래 설정의 동일성을 검사한다. 사용자 테마를 시험 삼아 삭제하지 않는다.

```sh
adb shell am instrument -w -e mode ui-check dev.mwidget.runtime.test/dev.mwidget.runtime.RuntimeSmoke
adb shell am instrument -w -e mode delete-check dev.mwidget.runtime.test/dev.mwidget.runtime.RuntimeSmoke
```

Galaxy S22에 v0.5.0을 무선 업데이트한 뒤 delete-check와 잠금 해제 상태의 ui-check를 통과했다. 실제 ⋮ 메뉴의 삭제 확인창을 열었다가 취소했고, 화면 재생성 전후 미리보기4개가 모두 표시됐다. 임시 테스트 테마의 두 리비전만 정리되었고 기존 사용자의 설정은 동일했다. 기존 테마의 파일49개도 업데이트 후 해시 동일성을 확인했다.
